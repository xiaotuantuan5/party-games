# party-games

聚会游戏 | A collection of party games

一个聚会小游戏合集，适合朋友聚会、团建、破冰等场景一起玩。每个人用自己的手机浏览器打开网页就能玩，不用装 App。

首页分“多人一起玩”和“一个人玩”两个分页，点开游戏能看规则，一键开房间；把邀请链接发给朋友，对方打开就能加入。

### 一个人玩

不用开房间，首页点开就玩，最高分保存在本机浏览器里。代码在 `apps/web/src/solo/`，纯前端运行，不经过服务端。

| 游戏 | 玩法 |
| --- | --- |
| 🚀 星际穿梭 | 3D 太空射击。拖动飞船躲陨石、击落飞碟，吃能量块拿护盾 / 散射 / 急速，每撑过 45 秒巨型战舰来袭。连续击杀分数翻倍。 |

## 技术选型

全栈 **TypeScript**：

- **服务端**：Node.js + [Socket.IO](https://socket.io/)。服务端是唯一可信的状态源，客户端只发送操作，服务端校验后给每个玩家下发“只含自己能看到的信息”的视图（比如卧底词不会发给别人）。
- **前端**：React + Vite，移动端优先。层层叠和星际穿梭用 [three.js](https://threejs.org/) 渲染 3D 画面（星际穿梭加了辉光后期，手机太卡时自动降低画质），层层叠塔倒时用 [cannon-es](https://github.com/pmndrs/cannon-es) 做物理模拟；这部分按需加载，不影响首页体积。
- **共享包** `@party/shared`：通信协议和每个游戏的视图 / 操作类型，前后端共用，改协议时两边都会有类型检查。

为什么这样选：

- 前后端同一种语言，协议类型只写一次，一个人就能维护整个项目。
- Socket.IO 自带房间、断线自动重连、WebSocket 不可用时降级到长轮询，适合手机网络。
- 聚会游戏是回合制、每秒消息很少，Node 单进程足够支撑大量房间；以后要横向扩容可以接 Socket.IO 的 Redis adapter。

### 实时游戏（秘境闯关）

秘境闯关是唯一的实时游戏，做法和回合制不一样：

- 角色移动、跳跃、滑翔、碰撞在各自的客户端计算（客户端权威），约每秒 12 次通过 `game:move` 上报位置，服务端校验数字范围、限流（每人最多 25 次 / 秒）后用 volatile 消息转发给同房间的人，丢包也没关系。
- 会影响所有人的事件（捡水晶、踩机关、开结界、全员到达终点、掉落次数）由服务端根据位置判定，只有这些状态变化时才推送完整的 `room:state`。
- 史莱姆的位置只由开局后的时间决定，各端按服务端时钟各自计算，不占带宽。
- 关卡数据在 `packages/shared/src/games/quest.ts`，前后端共用。画面全部由基础几何体 + `MeshToonMaterial` 三阶色带 + 背面外扩描边拼出来，没有外部美术资源；帧率持续过低时自动降分辨率、关阴影。
- 因为位置由客户端说了算，改包可以作弊，对朋友间的聚会游戏可以接受。

## 目录结构

```
apps/
  server/          Socket.IO 服务端
    src/rooms.ts   房间管理：创建 / 加入 / 断线重连 / 房主转移
    src/games/     每个游戏的规则引擎（实现 GameEngine 接口）
  web/             React 前端
    src/App.tsx    首页（游戏列表）、房间大厅
    src/fx.tsx     各游戏共用的全屏特效、彩带、音效开关
    src/sound.ts   Web Audio 实时合成的音效
    src/games/     每个游戏的界面
packages/
  shared/          前后端共享的协议与类型
```

## 开发

需要 Node.js 20+ 和 pnpm（`corepack enable` 即可）。

```bash
pnpm install
pnpm dev          # 服务端 :3001 + 前端 :5173（Vite 会把 /socket.io 代理到服务端）
pnpm typecheck
```

手机和电脑在同一个局域网时，可以用手机访问 `http://<电脑IP>:5173` 一起测试。

### 生产运行

```bash
pnpm build        # 打包前端到 apps/web/dist
pnpm start        # 服务端在 PORT（默认 3001）同时提供页面和 WebSocket
```

### 添加新游戏

1. 在 `packages/shared/src/games/` 定义视图和操作类型，并在 `GAMES` 中登记元信息（名称、图标、人数、时长、规则），在 `GAME_ORDER` 中决定首页顺序。
2. 在 `apps/server/src/games/` 实现 `GameEngine`（`setup` / `handleAction` / `viewFor` / `removePlayer`），并在 `ENGINES` 中注册。
3. 在 `apps/web/src/games/` 写界面，并在 `App.tsx` 中按 `gameId` 渲染。

## 已知限制

- 房间状态保存在内存中，服务端重启后房间会丢失。
- 轮到某个玩家时如果他断线，游戏会等他重连；房主可以随时结束本局回到大厅。
